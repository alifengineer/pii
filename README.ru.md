[English](README.md) | **Русский**

Go-библиотека для маскирования персональных данных (PII) в логах и сериализованном выводе. Два независимых подхода — можно использовать любой или оба сразу:

- **Рантайм-маскирование** — тег на поле + вызов `pii.Mask(v)`. Просто, динамично, через рефлексию.
- **Кодогенерация** — статические методы `Sanitize()`, генерируемые на этапе сборки. Без рефлексии в рантайме, быстрее на горячих путях.

---

## Установка

Как библиотека:

```bash
go get github.com/alifengineer/pii
```

Как кодогенератор (бинарь):

```bash
go install github.com/alifengineer/pii/cmd/sanitizer@latest
```

Убедитесь, что `$(go env GOPATH)/bin` есть в `PATH`, чтобы `go generate` мог найти бинарь `sanitizer`.

## Подход 1: Рантайм-маскирование через теги

Помечаете поля тегом и вызываете `pii.Mask`:

```go
package main

import (
    "fmt"
    "github.com/alifengineer/pii"
)

type User struct {
    ID    int
    Name  string `pii:"name"`
    Phone string `pii:"phone"`
    Email string `pii:"email"`
    PAN   string `pii:"pan"`
}

func main() {
    u := User{
        ID:    42,
        Name:  "Alice Smith",
        Phone: "+12025550199",
        Email: "alice@example.com",
        PAN:   "4111111111111111",
    }
    fmt.Println(pii.Mask(u))
    // {42 A**** S**** ***0199 a***@e***.com 411111******1111}
}
```

`pii.Mask(v any) any` возвращает **глубокую копию** с замаскированными полями — оригинал не мутируется. Вложенные структуры и указатели обходятся рекурсивно.

### Встроенные значения тега

| Тег | Константа | Поведение | Пример |
|---|---|---|---|
| `pii:"name"` | `pii.Name` | Оставляет первую руну каждого слова | `Alice Smith` → `A**** S****` |
| `pii:"phone"` | `pii.Phone` | Оставляет последние 4 символа | `+12025550199` → `***0199` |
| `pii:"email"` | `pii.Email` | Оставляет первую букву локальной части и домена, сохраняет TLD | `alice@example.com` → `a***@e***.com` |
| `pii:"pan"` | `pii.PAN` | Оставляет первые 6 (BIN) и последние 4 — PCI-DSS совместимо | `4111111111111111` → `411111******1111` |

### Кастомные маскеры

Регистрируйте свой маскер для любого тега:

```go
pii.Register("inn", func(v string) string {
    if len(v) < 4 {
        return "****"
    }
    return "********" + v[len(v)-4:]
})

type Company struct {
    INN string `pii:"inn"`
}
```

Сигнатура: `func(value string) string` (`pii.Masker`).

### Дженерик-функции

Если хочется вызывать маскеры напрямую (минуя `Mask`), они доступны как дженерики над `~string`:

```go
type MyEmail string

masked := pii.MaskEmail(MyEmail("alice@example.com"))
// "a***@e***.com" типа MyEmail
```

Доступны: `MaskName`, `MaskPhone`, `MaskEmail`, `MaskPAN`.

## Подход 2: Кодогенерация через `//go:generate`

Чтобы не платить за рефлексию при каждом вызове — сгенерируйте статические методы `Sanitize()` на этапе сборки.

### Быстрый старт

Объявите свой тип с методом `Sanitize() T`:

```go
package user

//go:generate sanitizer

type Email string

func (e Email) Sanitize() Email {
    // ваша логика маскирования
    return Email("...masked...")
}

type User struct {
    ID    int
    Email Email
}
```

Запустите:

```bash
go generate ./...
```

Генератор создаст `user_sanitize.go` рядом с исходником:

```go
// Code generated by sanitizer; DO NOT EDIT.
package user

func (v User) Sanitize() User {
    v.Email = v.Email.Sanitize()
    return v
}
```

Использование:

```go
log.Println(u.Sanitize())
```

### Как он определяет, что маскировать

Генератор смотрит на каждое поле структуры. Если у типа поля есть метод `Sanitize() T` — сгенерированный код его вызовет. Иначе — копирует поле как есть. Поддерживаемые формы полей:

- Значение: `Field T` → `v.Field = v.Field.Sanitize()`
- Указатель: `Field *T` → с проверкой на nil
- Слайс: `Field []T` → цикл по элементам
- Слайс указателей: `Field []*T` → цикл с nil-проверкой
- Вложенные структуры: зависимости автоматически подтягиваются и получают свой `Sanitize()`

### Флаги

| Флаг | Описание |
|---|---|
| `-type=Name1,Name2` | Генерировать только для перечисленных структур и их транзитивных зависимостей. Без флага — для всех подходящих структур пакета. |
| `-destination=path` | Путь выходного файла. По умолчанию: `<source>_sanitize.go` |
| `-check` | Сравнить с существующим файлом, выйти с ненулевым кодом при отличии. Используйте в CI, чтобы убедиться, что сгенерированные файлы закоммичены. |
| `-v` | Логировать в stderr решения по каждому полю и автоподтянутые зависимости |
| `-debug` | Сдампить разобранную модель как JSON в stdout, без генерации |

Генератор работает только через `go generate` — он использует переменные окружения `GOFILE` и `GOPACKAGE`, которые `go generate` выставляет автоматически.

### Пример: комбинация со встроенными маскерами

Можно использовать встроенные дженерик-функции внутри `Sanitize()` своих типов:

```go
package user

import "github.com/alifengineer/pii"

//go:generate sanitizer

type Email string
func (e Email) Sanitize() Email { return pii.MaskEmail(e) }

type Phone string
func (p Phone) Sanitize() Phone { return pii.MaskPhone(p) }

type User struct {
    ID    int
    Email Email
    Phone Phone
}
```

После `go generate` появится `User.Sanitize()`, вызывающий нужный маскер для каждого поля — без рефлексии, без тегов, только прямые вызовы методов.

## Какой подход выбрать?

| Используйте **рантайм** (`pii.Mask`) если... | Используйте **кодген** если... |
|---|---|
| Минимум настроек | Важна производительность (горячий путь, высокий RPS) |
| Типы из сторонних пакетов, нельзя добавить методы | Типы — ваши, методы добавить можно |
| Прототипирование или скрипты | Нужна compile-time проверка — новые поля видны в diff'е |
| Накладные расходы рефлексии не критичны | Хотите ноль рефлексии в рантайме |

Подходы не взаимоисключающие — кодген для горячих путей, `pii.Mask` для редких или произвольных логов.
